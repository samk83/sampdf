# 도면 비교 0단계 검증 결과 (PDF ↔ PDF)

Drawing Difference Checker 기획서 v1.0의 "PDF 비교 엔진부터 검증" 단계 결과다. 화면 없이 숫자로 판정했다.

- 엔진: `src/DrawingReview.Compare` (C#, OpenCvSharp4 4.13 / OpenCV 4.13, PDFium 렌더링; 처음 검증 때는 MuPDF.NET)
- 시험 도면: `tests/DrawingReview.TestData/ComparePairs.cs`가 만드는 가상 도면 쌍 (A3)
- 테스트: `tests/DrawingReview.Compare.Tests/CompareAcceptanceTests.cs` — **18개 모두 통과** (Linux)
- 실제 Revit·AutoCAD 출력 도면으로는 아직 시험하지 않았다.

## 비교 방식

1. **정렬**: 같은 크기이고 이미 잘 겹치면(겹침 정도 0.97 이상) 그대로 쓴다. 아니면 ORB 특징점과 RANSAC으로 이동·회전·균일 배율을 추정하고, ECC로 미세 조정한다. 조정 후 겹침 정도가 나빠지면 조정을 버린다. 수동 2점 정렬도 지원한다.
2. **차이**: 두 도면을 같은 해상도(기본 150dpi)로 렌더링하고 이전 도면을 개정 도면 좌표로 옮긴다. 한쪽의 그림 픽셀이 상대 도면의 "허용 오차 안 가장 어두운 값"보다 **밝기 70 이상 더 어두우면** 추가 또는 삭제로 판정한다. 흑백으로 자르지 않아서 옅은 선의 반 픽셀 차이를 걸러낸다.
3. **글자 비교**: PDF 단어와 위치를 비교해서 짝이 없는 단어를 변경으로 더한다. 작은 치수 글자 변경을 확실히 잡기 위해서다.
4. **정리**: 3픽셀 미만의 먼지는 지운다. 25픽셀 미만은 버리지 않고 "확인 필요(Low)"로 남긴다. 10pt 안의 차이는 한 영역으로 묶고, 위→아래, 왼쪽→오른쪽 순서로 번호를 붙인다.
5. **좌표**: 변경 영역은 개정 도면 페이지 좌표(pt)로 저장하고, 이전 도면 위치는 역변환으로 함께 기록한다.

## 발견한 점과 대응

| 발견 | 대응 |
|---|---|
| 흑백 판정 방식은 옅은 회색 점선이 반 픽셀 움직일 때 가짜 변경을 수십 개 만든다 | 밝기 차이(주변 최소값 비교) 방식으로 바꿈 |
| 작은 글씨(12pt)의 숫자 하나 변경은 픽셀 차이가 12개 정도라 Low가 된다 | PDF 글자 비교로 보강 → High |
| 회전된 개정본은 페이지가 틀에 맞게 더 축소된다 (0.95배 + 1° → 실제 0.927배) | 엔진은 실제 값을 정확히 찾음 (테스트 기대값 수정) |
| (MuPDF 시절) `Shape.DrawCircle`은 앞에 마무리(Finish)한 도형이 있으면 원을 그리지 않았다 | 시험 도면 생성기는 지금 PDFsharp(`PdfSketch`)로 그린다 |
| ORB 특징점 매칭은 A3 기준 약 1~1.5초 걸린다 | 같은 크기이고 이미 겹치면 생략. 대형 도면은 MVP에서 진행 표시·취소 제공 |

## 남은 위험

- **실제 도면**: 해칭, 이미지가 섞인 PDF, 스캔본, 글꼴 대체에서는 아직 검증하지 않았다. 스캔본은 민감도를 낮추고 정렬을 수동으로 해야 할 가능성이 높다.
- **반복 패턴**: 그리드만 있는 도면은 특징점이 엉뚱하게 맞을 수 있다. 정렬 품질이 0.6 미만이면 모든 결과를 Low로 표시하고 수동 정렬을 권한다.
- **이동한 객체**는 삭제와 추가 두 영역으로 나뉜다. 가까우면 한 영역으로 묶이고, 멀면 두 개로 나온다. MVP에서 "합치기"로 정리한다.
