# 변경 이력

작업 단위마다 무엇을, 왜 바꿨는지와 확인 결과를 남긴다. 최신 항목이 위에 온다.

## 2026-10-15 — Windows 한글 깨짐 수정

**무엇을**: `MuPdfUtf8Fix` 추가. 엔진을 처음 쓸 때 MuPDF.NET의 SWIG 문자열 콜백을 UTF-8을 명시한 콜백으로 다시 등록한다.

**왜**: Sam의 Windows 첫 실행에서 테스트 12개 실패 (엔진 8, App.Core 4). 모두 마크업 내용·작성자·책갈피 제목의 한글이 `"?��?"`로 깨짐. MuPDF.NET 3.28.2.4의 문자열 콜백에 인코딩 지정이 없어 Windows 기본 코드 페이지(CP949)로 읽기 때문 (Linux는 기본 UTF-8이라 통과했음). 인코딩이 지정된 통로를 쓰는 본문 검색·단어 읽기는 Windows에서도 통과해 원인을 좁힐 수 있었음.

**확인**: Linux 전체 261개 통과. 한글 마크업 읽기가 보정 콜백을 거치는지 확인하는 테스트 추가. **Windows 재확인은 Sam이 할 예정.** MuPDF.NET 버전을 올리면 이 보정을 다시 확인해야 함.

## 2026-10-12 — DWG/DXF 비교 개발 (치수, 화면, Cloud 내보내기)

**무엇을**
- 치수 비교: 선형·정렬 치수의 측정값·표시 문자·위치. 자동 문자 치수는 값(mm)으로 비교(mm·m 도면 같음), 덮어쓴 문자는 글자로 비교. 덮어쓴 문자 때문에 길이 변경이 숨는 경우 "check text override"로 알림.
- CAD 화면: CAD 도면을 같은 좌표 변환으로 PDF로 그려 기존 비교 창(겹쳐 보기·나란히 보기·Cloud·PDF/CSV/이미지 내보내기·프로젝트)을 그대로 쓴다. 변경 판정은 CAD 객체 비교 결과. 변경 목록에 설명 표시(예: `Dimension "6000" → "6500" [0]`).
- DXF/DWG Cloud 내보내기: 수락한 변경을 개정 도면 사본의 REVISION 도면층(빨강)에 구름 폴리선과 번호로 넣는다. 원본 덮어쓰기 거부.
- 엔진: 벡터 페이지 → PDF(`WriteVectorPdf`). 한글 CID 글꼴 도우미를 테스트 폴더에서 엔진으로 옮겨 공용화.
- 블록 회전·대칭이 호 각도와 글자 회전에 반영되도록 고침.
- 메뉴: Compare → Compare CAD Drawings (DWG/DXF)…

**왜**: Owner 결정 "C안" — 실제 DWG 샘플을 기다리지 않고 치수 비교와 화면을 먼저 개발.

**확인**: 전체 테스트 통과 (엔진 119, App.Core 94, Compare 18, Cad 29). 그린 PDF를 이미지로 눈으로 확인. **Windows 화면, 실제 AutoCAD DWG, AutoCAD에서 내보낸 Cloud 사본 열기는 아직 확인하지 않음.**

## 2026-10-12 — 0단계 엔진 검증

**무엇을**: C# 솔루션 뼈대, PDF 엔진 교체 경계(`IPdfEngine`/`IPdfDocument`), MuPDF.NET 구현, 안전 저장, 가상 도면 생성기, 검증 실행기, 자동 테스트 64개.

**왜**: 기획서 12장·17장에 따라 화면을 만들기 전에 "선택한 엔진으로 표준 PDF 주석을 저장하고 다시 열 수 있는가"를 먼저 판정하기 위해서.

**주요 결정**
- 엔진: MuPDF.NET (개인 로컬 사용이라 AGPL로 충분)
- 좌표: 엔진 밖에서는 "보이는 페이지 좌표"(회전·CropBox 반영, pt 단위)만 사용
- 파일은 메모리로 읽어 연다 (원본 잠금 없음 → 같은 경로에 안전하게 덮어쓰기 가능)
- 영역 하이라이트는 Multiply 혼합 반투명 사각형으로 저장
- Callout 지시선은 PDF 사전에 직접 기록 (MuPDF.NET의 CropBox 처리 오류 회피)

**확인**: Linux에서 `dotnet test` 64개 통과. 결과 PDF와 미리보기 이미지를 눈으로 확인. Windows, Acrobat, Bluebeam 확인은 아직 하지 않음.
