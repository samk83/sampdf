# 변경 이력

작업 단위마다 무엇을, 왜 바꿨는지와 확인 결과를 남긴다. 최신 항목이 위에 온다.

## 2026-10-12 — 도면 비교 0단계 검증 (PDF ↔ PDF)

**무엇을**: `DrawingReview.Compare` 엔진 (자동 정렬: Identity / ORB+RANSAC / ECC, 수동 2점 정렬, 밝기 차이 기반 비교, PDF 글자 비교, 잡음 제거, 영역 묶기와 번호, 겹쳐 보기 그림). 엔진에 단어 추출 `GetWords` 추가. 가상 도면 쌍 생성기와 검수 테스트 18개.

**왜**: Drawing Difference Checker 기획서. 화면을 만들기 전에 비교 정확도를 숫자로 확인하기 위해서. 결과는 [compare-validation.md](compare-validation.md).

**결정**: 별도 Electron/Python 앱 대신 현재 C# 프로그램 안의 모듈로 만든다 (Owner 승인).

**확인**: 전체 테스트 206개 통과 (엔진 115, App.Core 73, Compare 18). 실제 도면은 아직 시험하지 않음.

## 2026-10-12 — 1단계 화면 뼈대 (WPF)

**무엇을**: App.Core(ViewModel·확대 계산, WPF 비의존)와 WPF 앱 추가. 다크 테마, 메뉴, 도구줄, 문서 탭, 썸네일, 도면 캔버스(미리보기+고해상도 타일, 휠 확대·가운데 버튼 이동·스페이스 이동), 상태 표시줄, 패널 접기, 파일 끌어다 놓기, 암호 입력, 닫을 때 저장 확인. 엔진에 원시 RGB 렌더링(`RenderPage`) 추가.

**왜**: 기획서 12장 1단계(화면 시제품). 화면 시안(Drawing Review UI Mockup)의 배치를 따른다.

**확인**: Linux에서 App.Core 테스트 22개, 엔진 테스트 65개 통과. WPF 프로젝트는 Linux에서 컴파일만 확인. **Windows 실행 확인은 아직 하지 않음.**

## 2026-10-12 — 0단계 엔진 검증

**무엇을**: C# 솔루션 뼈대, PDF 엔진 교체 경계(`IPdfEngine`/`IPdfDocument`), MuPDF.NET 구현, 안전 저장, 가상 도면 생성기, 검증 실행기, 자동 테스트 64개.

**왜**: 기획서 12장·17장에 따라 화면을 만들기 전에 "선택한 엔진으로 표준 PDF 주석을 저장하고 다시 열 수 있는가"를 먼저 판정하기 위해서.

**주요 결정**
- 엔진: MuPDF.NET (개인 로컬 사용이라 AGPL로 충분)
- 좌표: 엔진 밖에서는 "보이는 페이지 좌표"(회전·CropBox 반영, pt 단위)만 사용
- 파일은 메모리로 읽어 연다 (원본 잠금 없음 → 같은 경로에 안전하게 덮어쓰기 가능)
- 영역 하이라이트는 Multiply 혼합 반투명 사각형으로 저장
- Callout 지시선은 PDF 사전에 직접 기록 (MuPDF.NET의 CropBox 처리 오류 회피)

**확인**: Linux에서 `dotnet test` 64개 통과. 결과 PDF와 미리보기 이미지를 눈으로 확인. Windows, Acrobat, Bluebeam 확인은 아직 하지 않음.
