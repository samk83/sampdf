## 지금 상태 (2026-10-16)
- **엔진(C#)**: PDF 열기·그리기(MuPDF.NET), 비교(OpenCvSharp, 글자/그림 구분), 구름·△·하이라이트를 PDF 주석으로 저장. Windows 한글 깨짐 수정 완료. 테스트 .NET 287개 Linux 통과.
- **웹앱(첫 버전)**: ASP.NET Core 서버(127.0.0.1:5180) + React 화면. 비교(나란히·겹쳐 보기·같이 이동·표시 수정·PDF 내려받기)와 투명 PNG가 동작. Owner가 Windows에서 실행 확인(최근 피드백 반영분은 Windows 재확인 전). 화면은 **확정 전 디자인**이라 다시 맞춰야 한다.
- **데스크톱(WPF)**: 마크업 작업 공간이 있으나 유지만 한다. 새 개발은 웹.
- **시안 확정**: A 배치 + 포커스 모드(F11) + S1 Slate 스킨, 영어 기본. `design/screens/index.html`.

## 확정된 큰 결정 (자세한 것은 docs/DECISIONS.md)
- 비교·검토 두 모드 모두 **오토캐드식 명령창**: 모든 메뉴를 명령으로 부름, 별칭(L, C, REC, RC, H, T, M, CO, E, LA, DI…), 좌표 입력(`100,200`, `@500<90`), Enter 반복·Esc 취소. 단축키는 오토캐드 방식으로 통일.
- **작도 1단계**: 선·폴리선·원·사각형·리비전 구름·글자·이동·복사·지우기, 내 레이어, 직교·격자, 내가 그린 것에 오스냅, 해칭(경계 그리기, 무늬 5개).
- **작도 2단계(나중)**: PDF 도면 선에 오스냅, 안쪽 클릭 해칭, PDF 원래 레이어 켜고 끄기, 축척 맞추기·거리 재기. MuPDF.NET에 `GetDrawings`·`GetOcgs`/`SetLayer`·선/원/폴리선 주석 API가 있는 것은 확인했지만 **실제 도면으로 시험하지 않았다**.
- 그린 것은 **PDF 주석(편집 가능)**으로 저장, 녹여 넣기는 내보낼 때 선택.
- 도면은 CAD에서 뽑은 PDF가 기본.
- **기본 언어 영어**, 다국어(한국어 등) 적용 예정. 명령 이름은 모든 언어에서 영어.
- 어두운 도면 보기(DV)는 도면 그림에만 거는 보기 옵션. 내보낸 PDF는 흰 종이.

## 설계에서 정할 것 (제안 목록 — 새 세션에서 회의로 확정)
1. **화면 구조**: 공통 틀(제목줄·리본·좌우 패널·명령창·상태 표시줄)과 모드(시작/비교/검토/투명 PNG/포커스)의 관계, 탭(열린 문서)과 모드 전환.
2. **부품 목록**: brand.md의 화면 뼈대를 React 부품으로 나누기 (Ribbon, Panel, CommandLine, StatusBar, Dialog, Toggle, LayerList…). 기존 `web/src/ui`, `web/src/compare` 중 살릴 것과 바꿀 것.
3. **명령 시스템**: 명령 등록표(이름·별칭·설명·단축키·실행 함수), 프롬프트 단계(점 입력·옵션·숫자), 자동완성, 리본 버튼·메뉴도 같은 명령을 부르게 하는 구조. 오타 제안.
4. **작도·마크업 모델**: 그린 것의 데이터 모양(선·원·구름·해칭·글자·레이어·스타일), 좌표(PDF 좌표 ↔ 화면), 되돌리기, 화면에 그리는 방식(SVG vs Canvas), 오스냅 계산 위치(브라우저 vs 서버).
5. **서버(API) 연결**: 주석 저장·불러오기, PDF 내보내기(편집 가능/녹여 넣기), 2단계용 선 정보·레이어 API 자리.
6. **다국어**: 글자 파일 분리 방식(라이브러리 선택 포함), 영어 기본.
7. **디자인 토큰 적용**: Tailwind 설정과 `design/tokens.css` 연결 방법.
8. **개발 순서**: 작은 단위로 나누기 (예: 토큰·공통 틀 → 명령창 → 비교 화면 다시 맞추기 → 검토 모드 + 작도 1단계 → 다국어 → 2단계).
9. **위험 확인**: PDF 선 추출을 실제 CAD PDF로 먼저 시험할지 (2단계 오스냅의 가능성 확인).

설계 결과는 문서(예: `docs/DESIGN-SPEC.md`)로 남기고 Owner 승인 후 4단계 개발로 넘어간다.

## 작업 규칙 요약 (CLAUDE.md와 Owner 선호)
- Owner는 코딩 초보. 한국어로, 어려운 용어는 쉽게 풀어서.
- 회의 → 비판적 검토 → 변경 계획 브리핑 → **"코딩 진행할까요?"** → "코딩해 / 코딩 진행해" 같은 명확한 지시 후에만 코딩. 질문이 오면 멈추고 회의로.
- 기능은 파일·폴더로 나누고 `docs/FEATURES.md`에 기록. 작업 단위마다 커밋(무엇·왜·확인 결과), `docs/CHANGELOG.md` 갱신.
- 확인하지 못한 것은 확인했다고 말하지 않는다 (특히 Windows).
- 브랜치 `claude/gracious-cori-qj4ytn`에서만 작업·푸시. PR은 요청할 때만.
