# kickoff — 기획서로 시작

새 프로젝트의 첫 단계다. 목적은 **코드를 쓰기 전에** 기획서를 단단하게 만들고, 다음 세션의 Claude(또는 다른 사람)가
이 프로젝트를 곧바로 이어받을 수 있도록 안내 문서를 남기는 것이다. 이 단계에서는 코드를 만들지 않는다.

Owner는 코딩 초보자다. 전문 용어는 처음 쓸 때 쉬운 설명을 붙이고, 결정이 필요한 것은 선택지·장단점·추천을 함께 보여 준다.
Owner의 개인 작업 원칙(회의 → 브리핑 → "코딩 진행할까요?" → 명확한 지시 후 작업)이 있으면 그것이 이 스킬보다 우선한다.

## 승인(권한) 안내 — 작업이 멈추지 않게
세션 설정에 따라 명령 실행(Bash: git, 테스트, 설치 등)마다 Owner의 승인이 필요할 수 있다. 승인 요청은 Owner가 그 세션 화면을 보고 있어야 처리되므로,
Owner가 자리를 비우면 작업이 그대로 멈춘다. 그래서:
- 시작할 때 한 번 알린다: "이 프로젝트에서는 git(저장·올리기), 테스트·빌드 명령을 자주 씁니다. 승인 창이 뜨면 '이 세션에서 항상 허용'을 고르시면 매번 멈추지 않습니다."
- 승인이 필요한 명령을 실행하기 직전에, 무엇을 왜 실행하는지 한 줄로 먼저 말한다 (예: "문서를 저장소에 올리려고 git push를 실행합니다. 승인 창이 뜹니다.").
- 지울·덮어쓸 수 있는 명령(삭제, 강제 올리기 등)은 '항상 허용'을 권하지 않는다.

## 진행 순서

### 1. 기획서 읽기
- 붙여 넣은 글, 파일, 문서 링크 어떤 형태든 받는다. 링크를 열 수 없으면 추측하지 말고 내용을 붙여 달라고 요청한다.
- 앱의 목적, 핵심 사용자, 주요 기능, 사용 환경(웹/PC 프로그램/휴대폰 앱), 화면 목록을 뽑아 정리한다.

### 2. 비판적 검토
무조건 동의하지 않는다. 아래를 짧게 정리해 보여 준다.
- 빠진 것: 예) 로그인 필요 여부, 데이터 저장 위치, 오프라인 사용, 오류 상황
- 모순되거나 애매한 것
- 위험: 기술적으로 어렵거나 비용·시간이 큰 부분, 법·개인정보 문제
- 더 단순하거나 나은 대안 (있으면)

### 3. 질문은 "진행을 막는 것"만
- 답이 없으면 설계가 크게 달라지는 질문만 묻는다 (보통 3~5개 이내).
- 사소한 것은 합리적인 기본값을 정하고 "이렇게 정했습니다, 바꾸려면 말씀해 주세요"라고 알린다.

### 4. 기술 선택 제안
- 사용 환경에 맞는 선택지 2~3개를 장단점과 함께 보여 주고 하나를 추천한다. Owner가 고른다.
- 클라우드 세션(Linux)에서 확인할 수 없는 환경(Windows 전용 프로그램, 휴대폰 실기기)이 있으면 그 사실과 확인 방법을 미리 알린다.

### 5. 프로젝트 안내 문서 만들기 (Owner 승인 후)
`templates/` 폴더의 틀을 채워 프로젝트에 만든다. 이미 같은 파일이 있으면 덮어쓰지 말고 내용을 합치거나 Owner에게 묻는다.

| 만들 파일 | 틀 | 내용 |
|---|---|---|
| `CLAUDE.md` | `templates/CLAUDE.md` | 프로젝트 요약, 진행 단계 체크리스트, 확정된 결정 요약, 자주 쓰는 명령. **다음 세션이 가장 먼저 읽는 파일** |
| `docs/PLAN.md` | `templates/PLAN.md` | 정리된 기획서 (검토·질문 결과 반영) |
| `docs/FEATURES.md` | `templates/FEATURES.md` | 기능별 담당 파일 지도 (지금은 틀만) |
| `docs/DECISIONS.md` | `templates/DECISIONS.md` | 결정 기록: 무엇을, 왜, 언제 |
| `design.md` | 하네스의 `rules/design.md` | 공통 디자인 규칙. **내용을 바꾸지 말고 그대로 복사** |

공통 디자인 규칙의 위치: 이 스킬 폴더 기준 `../../rules/design.md` (플러그인 루트의 `rules/design.md`).

### 6. 하네스 설치 확인
다음 세션에서도 스킬을 쓸 수 있도록, 하네스가 프로젝트 안(`.claude/skills/`, `.claude/rules/`)에 들어 있어야 한다.
`.claude/harness-version` 파일이 있으면 설치된 것이다. 없으면 하네스 저장소 `samk83/ai-company-harness`를 가져와 설치한다.

```bash
bash <하네스 저장소>/tools/install.sh <프로젝트 폴더>
```

(클라우드 세션은 프로젝트 설정의 플러그인을 자동 설치하지 않지만, 프로젝트의 `.claude/skills/`는 자동으로 불러온다.)

### 7. 커밋하고 다음 단계 안내
- 무엇을 왜 만들었는지 적은 커밋을 남긴다.
- 마지막에 짧게 보고한다: 정리한 기획 요약, 정한 기본값, 남은 질문, 그리고 **"다음: 시안 단계(design-board) — `/design`에 붙여 넣을 지시문을 만들어 드립니다"**.

## 하지 않는 것
- 코드, 패키지 설치, 빌드 설정 만들기 (설계·개발 단계에서 한다)
- Owner가 답하지 않은 중요한 결정을 마음대로 확정하기
